# Event Match · aipunks

[Технический пайплайн: от условий до карточек](docs/pipeline.md)

Умный подбор event-подрядчиков в Казахстане, хакатон #79-lite.
Flutter-каркас для Web, Android и iOS: адаптивная форма, до трёх карточек с фактами из профиля, объяснимые пустые результаты.

## Запуск

Проверяемая среда: Flutter 3.44.1 / Dart 3.12.1.

```sh
cd apps/event_match
flutter pub get
flutter run -d chrome
```

Для Android запустите эмулятор или подключите телефон и выполните `flutter run -d <device-id>` (`flutter devices` покажет устройства). Для iOS нужны macOS и Xcode. Настройку мобильных toolchain проверяйте через `flutter doctor`.

В VS Code/Cursor откройте корень репозитория, установите расширение Flutter, затем в Run and Debug выберите `Event Match · Chrome` и нажмите F5. Для телефона включите USB debugging, подключите Android по USB, разрешите отладку на экране телефона, выберите устройство через `Flutter: Select Device` и конфигурацию `Event Match · Phone (select device)`.

Сборка установочного APK для разработки:

```sh
flutter build apk --debug
```

Файл: `apps/event_match/build/app/outputs/flutter-apk/app-debug.apk` (путь от корня репозитория). Он предназначен для тестовой установки на Android, не для публикации в магазине. Для публикации потребуется отдельная release-подпись. Задачи `Event Match: build web` и `Event Match: build Android APK (debug)` также доступны через Run Build Task.

```sh
flutter analyze
flutter test
flutter build web
```

## Что уже работает

При открытии сразу отображаются заполненные карточки из каталога: цена, город, категория, языки, форматы и описание. Кнопка «Подобрать под событие» открывает фильтры справа на компьютере или на весь экран телефона. «Применить и подобрать» закрывает панель и показывает до трёх рекомендаций; выбранные условия остаются сверху. Закрытие формы без применения сохраняет текущую выдачу, «Сбросить фильтры» возвращает каталог. Фотографий в датасете нет — использованы иконки категорий.

Город, дата, формат, категория, бюджет, опциональные язык и часы. Занятые и не проходящие условия профили исключаются. Три явных результата: подобрали / категории нет / кандидаты не прошли условия. Порядок по стартовой цене и id стабилен. Флаги синтетики и восстановленных полей видны в карточках.

## Датасет

`data/catalog.csv` — копия предоставленного CSV без изменений. Рабочий JSONL содержит все 66 профилей, включая 13 синтетических профилей организаторов. Наши тестовые демопрофили в рабочую выдачу не попадают. Имена анонимизированы; флаги `synthetic`, `city_imputed`, `price_imputed` сохранены. HTML-превью используется только как справочный материал.

Воспроизводимое преобразование (из корня репозитория, Python 3):

```sh
python scripts/import_catalog.py data/catalog.csv apps/event_match/assets/data/catalog.jsonl
```

## Следующий этап

Улучшить индивидуальность объяснений на исходных профилях, затем добавить семантическое ранжирование и серверный AI-сервис. Сейчас подбор локальный, объяснения шаблонные с короткой цитатой описания, LLM и backend не реализованы. Полное описание раскрывается в карточке. API-ключей в клиенте быть не должно.

Подробнее: [архитектура](docs/architecture.md). Это каркас, не завершённое решение всех критериев хакатона.

## Основа для развития

Добавлено поле «Что для вас важно?» и единый типизированный запрос с валидацией. Локальный алгоритм пока не учитывает пожелания — это явно отмечено в форме. Асинхронный `RecommendationService` позволяет подключить backend без переписывания экрана; предусмотрены таймаут, повторная попытка и защита от устаревших ответов. Тема вынесена отдельно, проверки автоматизированы в GitHub Actions.

[План развития и контракт API](docs/development.md). Сервер, LLM и сохранение заказов между запусками пока не реализованы.
