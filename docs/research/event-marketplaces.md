# Прямые аналоги: экосистема поиска event-подрядчиков

Дата проверки: **23 сентября 2026 года**. Контекст: Event Match, Казахстан, каталог из 66 профилей. Исследование опирается на открытые официальные страницы и справочные центры. Таблица описывает заявленные функции; она не подтверждает качество сервиса, конверсию, доступность в Казахстане или существование открытого API. Предложения для Event Match ниже — авторский продуктовый вывод, а не заявления конкурентов.

## Что из этого следует для Event Match

В проверенном коде уже есть `ClientEvent`, `SavedSelection`, публикуемые профили, модерация и календарь с подтверждением месяца. `MatchingEngine` различает доступность живого профиля и демонстрационные даты. Поэтому развитие стоит строить поверх событий и сохранённых подборок. README местами описывает более раннее состояние; отсутствие функции в README не следует считать доказательством её отсутствия в коде.

Рекомендуемая связь данных:

```text
ClientEvent / EventBrief
  → MatchRequest → SavedSelection → Comparison
  → Inquiry → Quote → Booking → Review
                  ↘ BudgetLine
PublishedProfile → PricePackage + Availability + Portfolio
```

`Comparison`, `Inquiry`, `Quote`, `Booking`, `Review`, `BudgetLine` и `PricePackage` здесь — предлагаемые сущности, а не подтверждение их реализации.

Три наиболее ценные реализуемые функции:

1. **Сравнение 2–3 кандидатов внутри события.** Показывать одинаковые поля: стартовая цена, город, язык, формат, длительность, источник профиля, статус даты, подтверждённые факты и неизвестные условия. Сохранять выбор и заметку клиента. Это использует текущий каталог и `SavedSelection`, не требует транзакционной платформы. Проверка ценности: доля подборок, дошедших до осмысленного выбора; число возвратов к сравнению.
2. **Смета команды с типом цены.** Для каждой выбранной категории хранить бюджет и кандидата; различать стартовую оценку и согласованную сумму. Показывать сумму известных расходов, остаток и число позиций без цены. Старому каталогу назначать `priceKind=starting`, не выдавая эту сумму за окончательную. Проверка: доля выбранных позиций с известной единицей цены и составом пакета.
3. **Подготовленный запрос из брифа и жизненный цикл ответа.** Из города/даты/языка/часов/пожеланий собрать редактируемый текст и checklist вопросов о доступности, окончательной цене, составе и доплатах. Сначала достаточно сохранения/копирования; отправка подрядчикам — отдельное явно подтверждаемое действие. Позднее подключить кабинет заявок и `Quote` со сроком действия. Проверка: заполненность брифа, доля полученных сопоставимых предложений, время до первого ответа.

## Ограничения и решения, которые нельзя переносить механически

- **Стартовая цена ≠ итоговая стоимость.** Она пригодна для предварительного отбора, но состав пакета, длительность, логистика и другие условия могут изменить сумму. Нужен отдельный статус точности цены.
- **Календарь ≠ бронь.** Даже подтверждённая доступность не резервирует слот. Смена даты должна перепроверять все позиции команды, а не сохранять старое подтверждение.
- **Модерация ≠ гарантия качества.** The Bash связывает отзывы с бронированиями; [GigSalad прямо сообщает](https://help.gigsalad.com/article/47-how-it-works), что не верифицирует всех перечисленных исполнителей. Метки происхождения и полноты данных нужно отделять от доказанного опыта.
- **Платёжные гарантии требуют операционной системы.** У The Bash online payments в описанном процессе относятся к США; Tagvenue разделяет сценарии запросов и условия online payments. Нельзя обещать возвраты/escrow в Казахстане на основании интерфейса зарубежного аналога. Для MVP полезнее честные статусы, условия и возможность замены.
- **AI подтверждён только для конкретного сценария The Knot Upload List.** Из этого не следует, что у всех аналогов AI ранжирование; алгоритмы и API не исследованы. Для Event Match AI должен опираться на факты профиля и не заполнять неизвестные цену/доступность/опыт выдуманными значениями.
- **Малый демонстрационный каталог не измеряет рынок.** Не вычислять из 66 анонимизированных, частично синтетических профилей «среднюю цену по Казахстану», рыночный рейтинг или прогноз спроса.

Все ссылки проверены в указанную дату. На публичных страницах встречаются маркетинговые оценки масштабов/скорости; они не использованы как независимые доказательства эффективности продукта. Реальные конверсии, комиссии, тарифные ограничения и локальная применимость требуют отдельной проверки.
