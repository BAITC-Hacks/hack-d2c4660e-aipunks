# Расширенный демонстрационный каталог

Засеивание по ТЗ #79-lite: 500 записей, включая неизменённые 66 профилей организаторов и 434 новых. Новые записи не являются аккаунтами реальных подрядчиков. Формат JSONL и поля сохранены; `DEMO-*` обозначает добавленные нами записи, `synthetic: true` — вымышленные данные. Исходные 13 синтетических профилей организаторов сохраняют свои ID и отметки.

## Воспроизведение

Из корня репозитория:

```powershell
node scripts/seed_catalog.mjs
node scripts/audit_catalog.mjs
```

Из `apps/api`: `npm run db:seed` выполняет генерацию и импорт SQLite, `npm run catalog:audit` — отдельный аудит. Генерация работает без внешних зависимостей, сети и LLM; повторный запуск даёт идентичные записи, ID, календари и версию каталога. Источник — `data/catalog.original.jsonl`, исходный CSV не меняется. Импорт заменяет снимок каталога транзакционно, не удаляя кэш объяснений. Для обновления активного снимка перезапустите API и перезагрузите приложение.

Сумма по категориям больше 500: часть исходных профилей имеет несколько категорий. Новые профили распределены между Алматы и Астаной; сочетание «Зарубежье / Флорист» остаётся отсутствующим. В исходных профилях сохранены `max_hours: null`, восстановленные цены и города.

В новых анкетах различаются специализация, состав услуги и процесс подготовки, а также форматы, языки, цена, часы и календарь. Используются общие тематические блоки: уникальность текста не означает 500 уникальных профессий или отсутствие пересечения услуг.

## Проверка уникальности

Аудит проверяет все 124 750 пар записей, включая сравнения новых с исходными:

- 500 уникальных ID, 500 названий и 500 нормализованных описаний.
- 0 точных текстовых копий и 0 близких копий по описанному ниже порогу.
- Все исходные 66 записей совпадают со снимком по всем полям.

При сравнении названий и описаний игнорируются регистр, пунктуация, лишние пробелы и различие «е/ё». Из описаний дополнительно убираются числа и стандартное перечисление форматов — смена цены, количества или формата не маскирует копию. Для близких копий используется коэффициент Жаккара по тройкам соседних слов с порогом 0,80. Это воспроизводимая проверка текстового сходства, а не доказательство отсутствия любых смысловых пересечений. Исходные близкие по услугам лайв-бэнды сохраняются; подбор честно отмечает отсутствие подтверждённого уникального преимущества.

## Проверка подбора и API

- Осенний запрос «Алматы / Ведущий / свадьба / 06.10.2026 / 1 000 000 ₸»: 16 подходящих, показаны Кики, Эмилия, Лунный Ветер.
- На 05.10.2026: 13 подходящих, показаны Эмилия, Лунный Ветер, Лазурный Ветер.
- «Алматы / Флорист / свадьба / 10.10.2026»: одна карточка; редкость сохранена.
- Бюджет 1 ₸: `noEligible`; «Зарубежье / Флорист»: `categoryAbsent`.
- JSON ответа каталога — около 705 КБ в UTF-8, 587 тысяч символов при клиентском лимите 2 млн.
- Первый локальный подбор в контрольном запуске — 82 мс; остальные пять сценариев — 18–49 мс. Это измерение локального Dart-ядра, без сетевого запроса к GPT.

Регрессии проверяют детерминированный порядок, исключение занятых, максимум три карточки, три исхода, редкие категории, сезонную загрузку календарей, воспроизводимость генерации и импорт через HTTP/SQLite. Тесты API используют подменный GPT и не расходуют API-бюджет.
