# Локальный сервер, SQLite и GPT

## Подготовка

Нужны Flutter/Dart (как для приложения) и Node.js >=24.16. В этой версии используется встроенный node:sqlite, без внешнего СУБД-сервера и нативных npm-модулей.

1. Из apps/event_match: `flutter pub get`.
2. Из apps/api: `npm ci`.
3. Создать apps/api/.env по .env.example. Строка секрета: `OPENAI_API_KEY=ваш_ключ`. Не просто голый ключ.
4. Из apps/api: `npm start`.

Первый запуск импортирует каталог в apps/api/data/event-match.sqlite. База, WAL и .env исключены из Git. Перезапуск обновляет снимок каталога атомарно; кэш сохраняется. Отдельная команда импорта — `npm run db:import`; работающий сервер после изменения каталога надо перезапустить.

При запуске также создаётся первый администратор `admin@eventmatch.local`, если в базе ещё нет админа. Пароль генерируется в `apps/api/data/event-match.sqlite.admin-credentials.json` (исключён из Git) либо берётся из `ADMIN_PASSWORD` в `.env`. Email и имя настраиваются через `ADMIN_EMAIL` и `ADMIN_NAME`. Отдельная команда — `npm run admin:create`; повторный запуск сохраняет существующего администратора. [Подробная инструкция](feature-integration.md#запуск-и-первый-администратор).

Сервер использует один постоянный Dart worker из apps/event_match/tool/matching_worker.dart. На Windows путь к dart.exe определяется через Flutter SDK; при необходимости задайте DART_BIN в серверном .env.

## Chrome

Из apps/event_match:

```powershell
flutter run -d chrome --web-port=5173
```

API по умолчанию http://127.0.0.1:8787. В loopback-режиме без ALLOWED_ORIGINS CORS разрешает localhost/127.0.0.1 с любым dev-портом. Если ALLOWED_ORIGINS задан, действует только этот список; после изменения перезапустите сервер. LAN-режим не разрешает произвольные порты.

Выключатель «Объяснения от ИИ» позволяет переключаться на чисто локальную выдачу. GPT пишет сводки каталога и выбирает проверенную формулировку объяснения подбора из 1–2 предложений; [различия режимов](match-explanations.md). Без сервера или ключа остаются исходные описания и локальные факты. Сводки загружаются по 3 для отображаемой порции (до 4 вызовов на первые 12 карточек без кэша); после ошибки доступен ручной повтор.

## Android

Для стандартного Android-эмулятора адрес компьютера по умолчанию http://10.0.2.2:8787. В debug manifest разрешён локальный HTTP.

Для физического телефона:
- Телефон и компьютер в одной доверенной Wi-Fi-сети.
- В серверном .env: HOST=0.0.0.0 и LOCAL_API_TOKEN — случайная строка минимум 24 символа.
- Разрешить Node порт 8787 только в частной сети брандмауэра.
- Указать во Flutter адрес компьютера и тот же локальный токен:

```powershell
flutter run -d <device-id> --dart-define=API_BASE_URL=http://<IP-компьютера>:8787 --dart-define=LOCAL_API_TOKEN=<локальный-токен>
```

Это НЕ ключ OpenAI. Локальный токен присутствует в клиенте и служит только ограничением демо в доверенной сети. Не публиковать такой сервер в интернет. Release Android требует HTTPS; iOS ATS отдельно не настраивался.

## Ограничения вызовов и хранение

MAX_AI_CALLS_PER_DAY по умолчанию 100; 0 запрещает новые генерации, кэш остаётся доступен при настроенном ключе. Счётчик в SQLite, сутки UTC. Неуспешная попытка тоже учитывается. Дополнительно: 30 запросов редактора в минуту, не более 3 одновременно. Секрет не хранится в базе и не передаётся во Flutter.

Кэш включает модель, каталог, алгоритм, промпт, нормализованный запрос и готовые факты. Сетевые сбои не кэшируются. После изменения алгоритма/промпта нужно менять их версии. Базу сохранять на постоянном диске; её копия при запущенном WAL требует SQLite backup либо остановки сервера.

## Проверки

`npm test` — SQLite, общий Dart-алгоритм, mocked GPT, кэш, CORS, ошибочные версии/id, fallback. Тесты не читают .env и не вызывают платный API.

Явный живой smoke-тест при работающем сервере:

```powershell
node --env-file=.env src/smoke.mjs
```

Он может вызвать платный OpenAI API один раз при отсутствии кэша. Повторяет только успешный результат и сверяет дословное совпадение. 23.09.2026 проверено: три llm-ответа за ~2.7 секунды, повтор cached=true и identical=true. Предыдущая попытка со свободным длинным JSON достигла 6-секундного таймаута; fallback сработал. Это замеры одного локального прогона, не SLA.
