# Хранение и удаление данных помощника

В Firestore приватные результаты разбора запроса и векторы пользовательского запроса хранятся в `assistant_cache` с `ownerUid`. `expiresAt` записывается как Firestore Timestamp; `expiresAtMs` используется сервером для немедленной проверки срока годности. Счётчик запросов находится в `assistant_rate_limits/{sha256(uid)}` и содержит срок окончания текущего минутного окна.

Команда `backend/scripts/admin.mjs delete-account` в режиме просмотра показывает количество записей помощника, не выводя их содержимое. При выполнении после служебного маркера удаления и отключения Auth она удаляет все строки `assistant_cache` с данным `ownerUid`, затем его счётчик запросов. Удаление разбито на пакеты; повторный запуск продолжает очистку. Остальные шаги удаления аккаунта, включая переписку, связанные обращения в поддержку и их аудиты, сохраняются.

Сервер проверяет маркер `deletedAccounts/{uid}` внутри транзакции записи приватного кэша и счётчика: ранее начатый запрос не может заново сохранить их после удаления. Общие векторы публичных профилей не содержат текста пользовательского запроса и не принадлежат одному клиенту; такие строки очищаются по TTL. Старые строки без `ownerUid` невозможно отнести к конкретному пользователю через этот запрос; срок их хранения ограничен `expiresAt`, а приватные записи новой версии всегда должны содержать владельца.

В `firestore.indexes.json` заданы TTL-политики для `expiresAt` в обеих коллекциях: `ttl: true`, `indexes: []`. Это официальный формат `fieldOverrides`; индекс времени выключен, поскольку приложение не ищет записи по нему. Индекс `ownerUid` остаётся доступен для удаления по владельцу. [Справочник Firebase](https://firebase.google.com/docs/reference/firestore/indexes).

TTL — фоновая очистка: удаление не происходит точно в момент истечения. Поэтому чтение кэша самостоятельно проверяет срок, а удаление аккаунта не ждёт TTL. Политика действует на Timestamp, не на числовой `expiresAtMs`. Наличие конфигурации в репозитории не активирует её в облаке: после отдельного разрешённого развёртывания нужно проверить статус обеих политик в Firestore. Эмуляторные проверки не подтверждают работу облачного TTL. [Документация TTL](https://firebase.google.com/docs/firestore/ttl).

Регрессия `backend/test/assistant-cleanup.test.mjs` проверяет безопасный просмотр, удаление только собственных записей и повторную очистку после уже завершённого удаления. Отдельные тесты Functions проверяют срок чтения и запрет записи после маркера удаления.
