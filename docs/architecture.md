# Архитектура Event Match

## Компоненты

- Flutter: форма → MatchingController → RecommendationService.
- Pure Dart domain: нормализация, MatchingEngine, все нарушения, скоринг, факты, ослабления и hash каталога.
- ApiCatalogRepository: SQLite-каталог через локальный HTTP API, встроенный JSONL при недоступности. Снимок фиксируется на время работы экземпляра репозитория.
- LocalRecommendationService: полностью автономный подбор.
- ApiRecommendationService: локальный подбор, затем необязательная редактура GPT. Сбой сети не превращает результат в ошибку подбора.
- Node.js API: HTTP, проверка входа/версий/id, CORS, ограничения запросов, SQLite и официальный OpenAI SDK.
- Постоянный Dart worker: то же самое domain-ядро для серверной перепроверки. Серверу нужны Node и Dart, отдельной копии алгоритма на JavaScript нет.

Firebase не инициализируется. Ранее созданные публичные настройки сохранены для возможного возврата, но не являются зависимостью работающего API.

## SQLite

Файл `apps/api/data/event-match.sqlite` на компьютере, где работает сервер. Это **не база внутри браузера или телефона**. На устройстве доступен встроенный снимок JSONL.

Таблицы: contractors (id + исходный JSON), catalog_meta (hash/время импорта), explanation_cache (ключ/ответ/время), ai_usage (дата UTC/число попыток). Импорт атомарный, повторяемый, сохраняет старые кэши. WAL и busy_timeout включены; запросы параметризованы. Секреты и история заказов не хранятся в базе. Кэш содержит нормализованные результаты запросов и может сохранять производные от пожеланий данные — не публикуйте файл базы.

## Границы доверия

Клиент не посылает произвольный prompt или текст фактов. Сервер читает свой каталог, вычисляет ожидаемую тройку и отклоняет подмену id/версии. GPT самостоятельно пишет текст по main_fact/fit_fact, не управляет поиском. Сервер проверяет порядок, длину, числа, стоп-фразы и дубли; Flutter проверяет контракт и источник. Эти проверки не являются доказательством смысловой точности. Для каталога /v1/summaries принимает до 3 id и использует только серверные профили.

По умолчанию API слушает только loopback. LAN-режим требует локального токена минимум 24 символа. Для публичного интернета этого недостаточно: нужны HTTPS, полноценная аутентификация и ограничения по пользователям. CORS не заменяет аутентификацию.

Глобальные ограничения локального демо: 30 POST/мин, до 3 активных запросов, по умолчанию 100 попыток GPT в сутки (SQLite). Это ограничение вызовов, не гарантия денежного бюджета провайдера. Ключ только в серверном .env; логи не содержат ключа, prompt или пользовательских пожеланий.

## Асинхронность и детерминизм

Контроллер игнорирует устаревшие ответы. Общий таймаут подбора 10 секунд, HTTP-объяснения 8 секунд, GPT 7 секунд; загрузка каталога 2 секунды. Сводки каталога загружаются независимо от подбора, последовательно по 3 для отображаемой порции; HTTP-таймаут 9 секунд. Ошибка приостанавливает фоновую генерацию до ручного повтора. Совпадение запроса и версии гарантирует порядок, успешный кэш — тот же текст.

## UI

Сохранены пастельная тема, 1–3 колонки и боковая/полноэкранная форма. Новые подсказки — нативные кнопки с областью нажатия не менее 48×48, переносятся по ширине. Источник текста не кодируется только цветом. Подробности карточки показывают фичи и score; переключатель GPT недоступен во время запроса.
