# Развитие и контракт API

Реализованы локальный подбор v2, SQLite и безопасный GPT-редактор. [Запуск](local-backend.md), [формулы](pipeline.md).

## HTTP

- GET /health → ok, ai_configured, catalog_version, profiles.
- GET /v1/catalog → catalog_version, profiles (исходные поля JSONL).
- POST /v1/explanations → редактура уже выбранных карточек.

Тело POST:

```json
{
  "request": {
    "city": "Алматы",
    "date": "2026-10-06",
    "event_format": "свадьба",
    "category": "Ведущий",
    "budget_kzt": 1000000,
    "hours": null,
    "language": null,
    "preferences": ""
  },
  "catalog_version": "<SHA-256 текущего каталога>",
  "algorithm_version": "contrast-v2",
  "ids": ["HK-35215", "HK-42352", "HK-44923"]
}
```

Ответ: cards [{id, explanation, source}], reason, cached, catalog_version, algorithm_version.
source: llm или template. Порядок ответа тот же.
Ошибки: 400 вход/недоступное ядро, 401 локальный токен, 403 origin, 409 версии или подмена выбора, 413 большой запрос, 415 content-type, 429 лимит.
Отказ GPT — HTTP 200 с локальными текстами и reason, а не потеря рекомендаций.

## Честные ограничения

1. GPT пишет краткие объяснения по фактам. Проверки структуры и чисел не гарантируют семантическую точность; оригинальные описания остаются доступными. При ошибках — локальный текст без отметки ИИ.
2. Почти одинаковые профили помечаются как не имеющие уникального преимущества. Нужны дополнительные подтверждённые данные, а не уникальность ради уникальности.
3. Пожелания — лексические совпадения; «без конкурсов» нельзя надёжно трактовать как запрет конкурсов.
4. Веса из проектного документа — эвристика. Поправки за синтетику/восстановленные поля — свойства данных, не оценка человека.
5. Android проверяется тестами компонентов, не физическим устройством; текущие изменения не собирались в Web/APK по просьбе пользователя.
6. Для публичной эксплуатации нужны HTTPS, пользовательская аутентификация, мониторинг, резервное копирование SQLite и отдельная политика хранения кэша.
7. iOS-сеть и запуск не проверены; нужен Mac и настройка HTTPS/ATS.

## Следующие шаги

Отдельно зафиксирована [идея закрытой платформы с внутренней перепиской заказчика и подрядчика](product-ideas.md). Пока только направление развития, без реализации и изменения текущего объёма MVP.

- Размеченный набор качественных фактов с цитатами и оценка объяснений человеком.
- Отдельный разбор пожеланий с обработкой отрицаний, не замена фильтров произвольным ответом LLM.
- При необходимости свободная переформулировка: фактологическая валидация сложнее проверки чисел; вводить после eval-набора.
- База на устройстве (если потребуется изменяемый офлайн-каталог) — отдельная задача. Сейчас SQLite на локальном сервере, JSONL в клиенте.
