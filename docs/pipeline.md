# Event Match — реализованный пайплайн v2

Основано на документе «Event Match: было и стало — разбор нового пайплайна». Иллюстративные цены из документа не перенесены в каталог.

## Поток

```text
CSV → исходный JSONL → SQLite на локальном Node-сервере
                            ↓ GET /v1/catalog
Flutter → снимок каталога (при отсутствии сервера — встроенный JSONL)
        → нормализация → город/категория → все нарушения
        → скоринг прошедших → до трёх → контрастные факты
        → локальные объяснения + подсказки изменения условий
        → опционально POST /v1/explanations
            → перепроверка тем же Dart-ядром по SQLite
            → постоянный кэш → GPT-редактор → валидация
        → карточки; при любом отказе AI сохраняется локальная выдача
```

## Нормализация и данные

Канонические коды городов, форматов, категорий и языков заданы в `domain/normalization.dart`. Это типизированный эквивалент предложенного synonyms.json, без двух расходящихся словарей. Например, Almaty/алма-ата/Алматы, MC/тамада/Ведущий, wedding/свадьба, ru/русский. Неизвестные значения нормализуются по регистру и пробелам, но не угадываются. В форме используются русские селекты.

Исходные профили не переписываются; сравнения канонические. Версия каталога — SHA-256 канонического JSON всех полей, профили отсортированы по id. Порядок ключей и запись целых чисел унифицированы в Dart и Node; совместимость проверена тестом. Новая версия инвалидирует AI-кэш по ключу, не удаляя старые записи.

## Все нарушения и сводка

Пул — город и категория. Для каждого профиля сохраняется множество:
`format, language, hours, busy, budget`.
Основная причина — первая в этом приоритетном порядке. Сумма основных причин плюс прошедшие равна размеру пула. Подрядчик может нарушать несколько условий, но не учитывается дважды в сводке.

Часы проверяются только при заданной длительности и ненулевом `max_hours`. Календарное окно: 23.09–31.12.2026. Площадки проходят те же фильтры.

## Скоринг

`score = provenance × (0.30 budget + 0.20 focus + 0.20 description + 0.15 language + 0.15 hours)`.

| Фича | Расчёт |
| --- | --- |
| budget | r=цена/бюджет; r<0.6: 0.5+0.5r/0.6; 0.6≤r≤0.9: 1; иначе 1−4(r−0.9) |
| focus | 1−(число форматов−1)/5 |
| description | min(1, число различных совпавших ключей/2); словарь формата и слова пожеланий |
| language | Задан язык: 1; иначе ru+kk: 1, один из них: 0.5, ни одного: 0 |
| hours | null: 0.5; без запроса: min(1,max/8); с запросом: min(1,(max−запрос)/4) |
| provenance | ×0.9 отдельно за каждый восстановленный город/цену; ×0.85 за синтетику |

Фичи ограничены диапазоном 0..1. Сортировка: score ↓ → цена ↑ → id ↑. Веса — эвристика из документа, а не обученная модель. Больший бюджет и меньшее число форматов не доказывают качество исполнителя. На карточке это явно оценка соответствия, не рейтинг.

## Объяснения

Для каждого кандидата собираются факты о цене, языках, часах, форматах и цитаты вокруг совпавших слов. Выбирается отличающийся от соседей факт с наибольшим взвешенным вкладом своей фичи. При равенстве порядок типов фиксирован. Общие дата/формат/бюджет вынесены в сводку.

Две фразы: главный факт + стартовая цена и запас бюджета, с предупреждением об оценённой цене. Цитаты не начинаются автоматически с приветствий; стоп-лист общих рекламных фраз исключается. Проверки ограничивают длину до 300 символов на рабочем каталоге.

Похожие цитаты сравниваются по русским токенам, чтобы замена латинского названия группы не считалась новым преимуществом. Это лексическая эвристика, не доказательство семантической эквивалентности. Если отличий нет, выставляется `equivalent=true`, UI сообщает об ограничении данных. Одинаковые факты намеренно не маскируются выдумками.

## Подсказки

Показываются при нуле или 1–2 прошедших, максимум три:
бюджет, снятие языка, уменьшение часов, другой формат, даты ±1..7; при пустом пуле — другой город.

Каждый предложенный запрос **полностью перепроверяется**. Для бюджета выбирается минимальный достаточный порог с округлением вверх до 10 000 ₸; учитываются только действительно прошедшие на этом пороге. Для города считаются подходящие под все условия, а не просто размер каталога.

Подпись: новое значение, итоговое число вариантов и количество новых профилей. Смена даты/формата может убрать ранее доступных — «+N новых» не означает прирост итогового размера. Ранжирование подсказок: новые профили ↓, стоимость изменения (язык, формат, часы, дата, бюджет, город), близость даты, стабильная подпись. Кнопка меняет один параметр и перезапускает подбор.

## AI и кэш

Сервер получает нормализованный запрос, версии и id выбранных карточек, **не принимает клиентские факты на веру**. Он перепроверяет выбор тем же Dart-ядром, используя SQLite. Состав/порядок не может поменять ни GPT, ни ответ сервера.

Один вызов OpenAI Responses API на тройку, модель `gpt-4o-mini-2024-07-18`, temperature=0, timeout 6 секунд, без автоматических повторов. Seed не используется: повторяемость опирается на детерминированный код и постоянный кэш, а не на обещание одинаковой генерации.

**Отличие от свободной генерации в проектном документе:** GPT выбирает индексы из допустимых формулировок. Модель не может добавить новую мысль, поменять число или перевернуть смысл. Финальный HTTP-ответ всё равно содержит `{cards:[{id,explanation,source}]}`. Сервер и Flutter проверяют id, порядок и точное вхождение текста в разрешённый набор. Эквивалентные карточки остаются шаблонными.

Кэш SQLite: нормализованный запрос + hash каталога + версия алгоритма + версия промпта + модель + факты карточек. Одновременные одинаковые запросы объединяются. Сетевые ошибки не кэшируются; успешные проверенные ответы переживают перезапуск. Источник `llm/template` виден в UI.

## Проверки и ограничения

Сценарии — в README; скрипт `tool/audit_catalog.dart` печатает реальную выдачу и время локального алгоритма. Тесты перебирают все города/категории на пяти датах, проверяют каждую подсказку повторным подбором, ограничения, нормализацию и обработку почти одинаковых профилей.

Отрицания и сложные пожелания не понимаются семантически. Неповторяемость для неразличимых данных не гарантируется. Скорость внешнего API не гарантирована: таймаут переводит ответ на локальные факты.
