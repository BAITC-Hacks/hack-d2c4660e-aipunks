# Интеграция кабинетов, помощника и сообщений

## Источники и выбранный backend

Перенесена накопительная цепочка GitHub: `codex/account-management` →
`codex/event-planning` → `codex/ai-assistant` → `codex/features` (`386b765`).
`codex/preview-fixtures` указывает на тот же итоговый коммит. Перенос из общей
базы `7a23420` выполнен по модулям, без смены рабочей ветки и отката текущего
дизайна, 500-профильного каталога, GPT-объяснений и избранного.

Backend по умолчанию — существующий **Node.js + SQLite**, без Firebase.
Firebase-адаптеры сохранены как отдельная реализация контрактов; они не
используются `main.dart`. Деплой Firebase и миграция удалённых данных не выполнялись.
Переписка в новых ветках была только описана как идея — её локальная реализация
добавлена при интеграции.

## Где находятся функции

- Главная `/`: прежний каталог из 500 демонстрационных/анонимизированных анкет.
- Звёздочка в шапке: ИИ-помощник в правой панели; при закрытии диалог остаётся
  в памяти приложения. Смена аккаунта очищает его.
- Иконка сообщений: правая панель списка переписок; внутри неё открывается диалог.
- Меню пользователя → «Мой кабинет»: мероприятия, подборки, план, настройки.
  Переключатель кабинета открывает инструменты подрядчика; сотрудникам доступна админка.
- Меню пользователя → «Опубликованные подрядчики» (`/catalog`): реальные аккаунты,
  чьи анкеты одобрены модератором. Здесь кнопка «Написать» под профилем открывает
  переписку. У демонстрационных анкет кнопка неактивна: у них нет получателя.
- Подрядчик: черновик профиля → проверка → публикация; актуальный календарь занятости.
- Админка: проверка анкет, снятие публикации, блокировки, модераторы, журнал действий.
- План события: бюджет, выбранные специалисты из сохранённых подборок, задачи,
  заметки; сохранение защищено версией от перезаписи из другого окна.

## Запуск и первый администратор

Из `apps/event_match` выполните `flutter pub get`, из `apps/api` — `npm ci`.
Перезапустите API (`npm start`) и Flutter dev-server после остановки старого процесса.
Web/APK-сборка для этого не нужна.

Зарегистрируйте аккаунт в интерфейсе. Выдача администратора доступна **только
в локальном терминале владельца сервера**, не через публичный API:

```powershell
cd apps/api
npm run admin:grant -- your-email@example.com
```

Повторно войдите в аккаунт. В переключателе кабинета появится «Админка».
Для проверки общения создайте отдельные аккаунты клиента и подрядчика в разных
браузерных сеансах. Подрядчик сохраняет и отправляет анкету; администратор
одобряет её; клиент находит её в опубликованном каталоге и нажимает «Написать».

## Помощник и расходы

`POST /v1/assistant`: текст → OpenAI Responses со строгой JSON-схемой → проверка
условий сервером → детерминированный отбор → ответ и типизированные кнопки.
Модель не выдаёт ID кандидатов, не меняет цены и не подтверждает бронирование.
Уточнения кнопками, смена даты/бюджета, исключение кандидата и ручной режим
не вызывают GPT. Отрицания проверяются по подтверждённым цитатам признаков;
неизвестное пожелание помечается как неподтверждённое, а не как выполненное.

Этот помощник ищет в текущем **демонстрационном каталоге из 500 анкет**. Словарь
подтверждённых смысловых признаков из веток покрывает исходные 66 анкет; для
остальных отсутствие доказательств остаётся неизвестностью. Живой каталог
использует отдельную проверку опубликованных профилей и актуального календаря.
Общий бюджет события не делится автоматически и не становится лимитом подрядчика.
При нескольких категориях помощник уточняет, кого искать первым.

Кэш SQLite зависит от модели, версии каталога/признаков/алгоритма и текущего дня.
Одновременный одинаковый разбор объединяется. Максимум ответа — 1200 токенов,
таймаут — 8 секунд, автоматических повторов нет. Дневной лимит
`MAX_AI_CALLS_PER_DAY` общий с прежними GPT-описаниями карточек.
`assistant_usage` хранит количества токенов без ключа и текста запроса.

Обычные `npm test` / `flutter test` не обращаются к OpenAI.
Платный тест запускается **только явно**:

```powershell
cd apps/api
npm run assistant:smoke
```

Он ограничен 6 вызовами `gpt-4o-mini-2024-07-18`, каждый до 1200 выходных токенов.
Проверенный запуск 23.09.2026: 6/6 сценариев, 17 660 входных + 524 выходных токена.
Проверены полный запрос, исправление одного поля, отрицание, несколько категорий,
бюджет всего события и требование выдумать подрядчика. Это smoke-проверка, не
доказательство безошибочности модели на любых формулировках.

## Границы локальной версии

- Пароли хешируются scrypt с индивидуальной солью. Сервер хранит хеши случайных
  сессионных токенов; клиент держит токен только в памяти. После перезагрузки
  вкладки нужен повторный вход. Сеанс на сервере живёт 12 часов.
- Email пока не подтверждается; Google-вход и восстановление по почте в локальном
  режиме не подключены и не предлагаются как рабочие действия.
- Приватные данные проверяются по серверному сеансу. `uid`/`actorId` от клиента
  не дают права читать чужие события, назначать роли или читать переписки.
- Сообщения — текст до 4000 символов, обновление раз в 5 секунд; последние 200
  сообщений отображаются в диалоге. Вложения, push, поиск по истории и отметки
  прочтения пока не реализованы. Смена аккаунта удаляет приватную панель из UI.
- Переписка не оформляет бронь/оплату/договор. Удаление аккаунта пока сохраняет
  запрос на обработку, а не обещает немедленное физическое удаление данных.
- Это локальный прототип. Для публичного запуска нужны HTTPS, почтовый сервис,
  постоянное управление секретами, резервное копирование, отдельные лимиты
  пользователей и эксплуатационная проверка. Не открывайте dev-API в интернет.

## Проверки

Серверные тесты: права владельцев/админов, модерация и версии, публикация,
календари, приватность переписки, двусторонний ответ, повторная отправка,
SQLite-кэш и лимит GPT; матрица фильтров и уточнений из исходных веток.
Flutter: кабинеты, маршруты входа, план, помощник, транспорт, общая правая панель,
кнопки и история, сообщение с повтором после ошибки, прежние избранное/карточки.
Сборки Web/APK при интеграции не запускались.

Итог проверки 23.09.2026: `flutter analyze --no-pub` — без замечаний;
`flutter test --no-pub` — 167 успешных тестов, 10 opt-in визуальных пропущены;
`npm test` — 66 успешных тестов. Дополнительно отдельно выполнены 2 визуальных
теста новых панелей при 1440×1000 и 375×812 и просмотрены полученные изображения.
